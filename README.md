# Ripasso Italiano

A personal Italian practice app (called "Ripasso" in the app; *ripasso* means going back over your material), built around typed answers, with a speaker beside the Italian to hear it read aloud by the device's own voice. The whole app is `index.html`; open it in any browser.

The app is used in two places: as a private claude.ai artifact (with cloud sync), and as an app installed on an Android phone from this repository's GitHub Pages site, https://grantgilford.github.io/ripasso-italiano/ (it works offline and offers each new version merged to `main`). This repository is where changes are made and reviewed. The tag `v7.2` marks the known-good starting version.

To install it on Android: open the address above in Chrome, tap the menu (⋮) and choose **Install app** (or **Add to Home screen**). To bring progress across from another copy, use **You → Your data → Save backup file** there, then **Load backup file** in the installed app.

Progress is saved on the device, in the browser's database (IndexedDB, from version 9.26; **You → Your data → Storage** shows where, how much is saved and the room left). Keep a backup file somewhere safe all the same: it is the one copy that doesn't depend on the device. `docs/storage-room.md` has the detail.

To report a problem: flag the item under its answer and tap **Report it**, or use **You → Your data**, which also lists the answers you accepted (to suggest for everyone) and any errors the app noticed (to report). A report opens as a public issue in this repository, filled in for you (it needs a GitHub account), or can be copied and sent any way you like; nothing is sent unless you tap. Reports go where `REPORT_TO` in `index.html` says, so a fork changes that one line. `node tools/read-reports.js` reads them back; see `CLAUDE.md`, Working through reports.

What changed in each version is in `CHANGELOG.md`, and each version is tagged on GitHub (`v9.1`, `v9.2`…). The lessons, words and exercises inside `index.html` are laid out one entry per line, so a pull request shows each change to them line by line. See `CLAUDE.md` for how work is done here, and `docs/` for the content guide, the design system, the catalogue of exercise types (`docs/exercise-types.md`) and the original spec.

To run the checks (needs Node.js): `npm install` once, then `npm test` for everything (about 17 minutes), `npm run test:quick` for what needs no browser (about a minute), or `npm run check` for the content check alone. `npm test` runs every suite to the end and finishes with a table of suite, result, number of checks and time: the content check; the reports (`tools/test-reports.js`); the learning rules case by case, scheduling, the streak and the answer checker (`tools/test-rules.js`); every exercise of every item, built and checked without a browser (`tools/test-course.js`); the storage (`tools/test-storage.js`); that saved progress is safe (`tools/test-progress.js`); the interface against the design system (`tools/test-ui.js`); the installed copy (`tools/test-install.js`); the speed-ups (`tools/test-speedups.js`); how sessions are put together (`tools/test-sessions.js`); the wrong options and answer panels (`tools/test-choices.js`); exercises answered right and wrong through the real screen (`tools/test-items.js`, `tools/test-verbs.js`); Firefox and WebKit (`tools/test-browsers.js`); and the app's speed (`tools/test-perf.js`). GitHub runs the same suites side by side on every pull request, with the speed compared against `main`'s; once a week it also checks the tests themselves, by putting small faults into a copy of the app and seeing that a suite notices (`tools/test-the-tests.js`).
